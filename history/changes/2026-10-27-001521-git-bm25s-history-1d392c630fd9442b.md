## Why

실제 FabGym 기록 검토에서 검색 오탐·중복·최신성·커밋범위·기록충돌과 설치본 불일치를 확인했다. 에이전트가 현재 코드와 연구 근거를 구분해 확인하도록 고친다.

## How

0.6.0으로 통합했다. commits --file/--ref/--follow/--diff/--json은 선택 ref의 Git 객체와 full SHA로 파일 변경·명시 연결·co-change·경로 후보를 구분한다. 실제 engine external_solver.py에서 수정 커밋2개와 별도 기록후보1개를 확인했고, 코드현재유효성이나 실험효과는 ancestry만으로 단정하지 않는다.

BM25S만 사용해 정확한 식별자 우선·문서별1개(선택2개)·본문발췌/줄·실제 확장끄기·종류/상태/경로필터·한글공백정규화·검색실패진단을 추가했다. 원문에 식별자가 없는 정정 기록은 직접연결 context로 보여주며 검색일치로 가장하지 않는다. 기존 capsule은 snapshot이므로 --query로 새 근거를 확인한다.

파일잠금/원자적쓰기/충돌없는신규ID, 날짜와UTCoffset의 결정적정렬, commit경계와선택적bookkeeping, 기본읽기전용과명시적recall --update, 관계/중복/메타데이터lint, --base finish 및미추적history안내, blocked보관보호와위험유지요약, 버전/기능확인/동일payload설치도구를 구현했다. SKILL 진입문서는 조건별상세참조로 줄였다.

세 구현 에이전트가 별도 작업트리에서 검색·Git근거·저장안정성을 담당했고 부모가 통합했다. 교차검토에서 CLI속성누락·잘못된JSON·읽기부작용·정정누락·보호경로rename우회·merge근거누락·특수경로줄번호·출력크기 문제를 추가 재현해 수정했다. 독립 전방검증에서 실제파일조회, 한국어결정탐색, 임시저장소 선택커밋/정정/capsule/finish를 수행했다. 무관한staged작업은거부되고무관한초안은커밋되지않았으며 읽기명령의파일/index변경0을확인했다.

전체105테스트성공(기준38), py_compile·Ruff치명오류검사·diff whitespace·skill quick_validate 성공. 고정26질의에서 top1근거15/18→18/18, 근거없음의올바른무응답2/8→8/8이다. 이는 작은합성진단세트이며일반의미검색이나에이전트작업시간개선을입증하지않는다. 실제FabGym에서 external_solver.py 관련기록단독1위, OpenCGS상위8개고유문서8개,없는식별자0개, Git SHA직접조회안내, Dyssol최신daily10/26 선택, --kind decision 수리상한결정0056 확인 및모든발췌원문줄일치를검사했다.

## Risks / Follow-Ups

한국어 조사·동의어·한영 의미 대응은 공유 어휘가 없으면 여전히 제한된다. Git rename/merge 단순화는 휴리스틱이며 squash/revert의 현재 효과를 자동 추론하지 않는다. 선택ref에 명시 연결이 없으면 후보로 남긴다. POSIX fcntl 잠금과 NumPy가 필요하며 Linux에서 검증했다. 설치는 명시 경로에 같은 payload를 복사하고 기존 디렉터리/링크를 sibling backup으로 보존한다. 원격 push/PR와 다른 FabGym 코드/기록 정리는 수행하지 않는다.
